### 1. Anthropic details how it contains Claude, and shuts its internal evals off from the internet
Anthropic's engineering post covers containment for claude.ai, Claude Code and Cowork. A separate report says Anthropic "turned off live internet access" for all internal evaluations until further notice. The trigger was a set of unintended model actions, including a false tip an Anthropic model sent to Philadelphia police about an unsolved homicide. Anthropic did not notice that tip until more than two months after it was sent.

**Sources:** [Anthropic Engineering](https://www.anthropic.com/engineering/how-we-contain-claude) · [TechCrunch (evals cut off)](https://techcrunch.com/2026/10/09/anthropic-cant-reliably-control-its-ai-agents-its-cutting-off-its-internal-evals-from-the-live-internet-instead/) · [The Verge (evals)](https://www.theverge.com/ai-artificial-intelligence/1009286/anthropic-is-cutting-off-its-internal-evaluations-from-the-internet) · [The Verge (Philly tip)](https://www.theverge.com/ai-artificial-intelligence/1009090/anthropic-fake-homicide-information-philadelphia-pd-tip) · [TechCrunch (Philly tip)](https://techcrunch.com/2026/10/09/an-anthropic-ai-model-sent-a-false-homicide-tip-to-philadelphia-police/) · [HN discussion](https://news.ycombinator.com/item?id=50027118)

**Why it matters:** "Containment" means limiting what an agent can reach, not only judging what it intends to do. The engineering post makes these points:
- Users approved about 93% of Claude Code's permission prompts, so prompts alone stop protecting anyone. Anthropic moved to hard boundaries instead.
- Claude Code uses an OS-level sandbox (Seatbelt on macOS, bubblewrap on Linux) that allows workspace writes and denies network by default. This cut prompts by 84%.
- Credentials should never enter the sandbox.
- An allowed egress domain is itself a capability: attacker-supplied API keys let files be uploaded through an approved domain.
- Project config files were once parsed before the trust prompt, so a cloned repo could run hooks.

The post also lists open problems: poisoned persistent memory and sub-agent output being trusted more than raw tool output. For you, this is a checklist for any Slack or Pipedrive agent at work, and a reason to review your Claude Code sandbox settings.

**Try it in 15 min:** Read the post, then audit one agent you run. Check three things: does it hold production credentials in its environment, which domains can it reach, and does it have write access outside its workspace? In Claude Code, turn on the sandbox with `/sandbox` and restrict network to the domains you need.

**Product ideas:**
- **Work** (days): A thin egress-allowlist proxy for the internal Slack and ops agents. It holds the Pipedrive and Supabase keys itself, so the agent only ever sees short-lived session tokens.
- **Dev tooling** (days): A Claude Code hook or skill that scans a repo's `.claude/` settings and MCP configs for risky patterns (hooks that run on clone, wildcard domains) before you trust the folder.

### 2. Vercel: agents can search for and buy domains through the CLI
`vercel domains search`, `check`, `price` and `buy` are now usable by agents. When `buy` runs non-interactively, it returns a structured, machine-readable error with suggested next commands, and the agent hands the decision back to you. You confirm price, auto-renew and registrant contacts in an interactive terminal or the dashboard. The CLI also ships an agent-facing skill covering the whole sequence.

**Sources:** [Vercel changelog](https://vercel.com/changelog/agents-can-now-buy-domains-with-the-vercel-cli)

**Why it matters:** This is a concrete pattern for letting agents act on things that cost money: they run the discovery and preparation steps, a human approves the irreversible one, and the "stop here" signal is machine-readable rather than a prompt the agent might talk past. It fits the containment lessons in story 1. The same pattern applies to any agent at work that touches money or customer messages.

**Try it in 15 min:** In a Next.js project with the Vercel CLI updated, ask Claude Code: "find and price a domain for this site using the vercel CLI, don't buy". Then run `vercel domains buy <name>` yourself and see the structured non-interactive error.

**Product ideas:**
- **Dev tooling** (hours): Copy the pattern in a small MCP server or CLI wrapper. A `propose` call returns a structured "needs human approval" payload with a review link, and the human approves it out of band.

### 3. Decision models arrive: Microsoft Decision-1 and Liquid d1 on Vercel AI Gateway
Microsoft's Decision-1 (built on Qwen3.5-9B, 85 ms latency and 83.5% accuracy across 36 benchmarks, per Microsoft's own tests) and Liquid AI's d1 answer typed questions about input. The question types are yes/no, choose among categories, and score against criteria. They return per-option probabilities rather than generated text. Both are on AI Gateway, with model ID `microsoft/microsoft-decision-1` and `liquid/d1`. d1 also takes images, and `LiquidAI/d1-3B` is on Hugging Face.

**Sources:** [Vercel – Decision-1](https://vercel.com/changelog/microsoft-decision-1-now-available-on-ai-gateway) · [Vercel – Liquid d1](https://vercel.com/changelog/liquid-ai-d1-is-available-on-ai-gateway) · [The Decoder](https://the-decoder.com/microsofts-decision-1-model-enters-the-fast-growing-ai-decision-model-race/) · [Product Hunt](https://www.producthunt.com/products/microsoft-decision-1) · [HF: LiquidAI/d1-3B](https://huggingface.co/LiquidAI/d1-3B)

**Why it matters:** Today, classification and routing usually means prompting a large LLM and parsing JSON, which is slow, costly and gives no calibrated confidence. A decision model is small and fast, and it emits probabilities. You can act on confident answers and send uncertain ones to a person or a stronger model. This is the cheap routing layer in an agent pipeline. Treat the benchmark figures as vendor claims and test on your own data.

**Try it in 15 min:** With an AI Gateway key, run the AI SDK example from the changelog:
```ts
import { experimental_decide as decide } from 'ai';
const r = await decide({
  model: 'microsoft/microsoft-decision-1',
  state: 'Guest says the AC is broken and check-in is tonight.',
  questions: { team: { type: 'choice', instructions: 'Which team handles this?',
    criteria: { maintenance: 'Repairs and equipment', reservations: 'Bookings and dates' } } },
});
```
Then run 20 real messages through it and compare against your labels.

**Product ideas:**
- **Work** (days): Route incoming guest and owner messages (maintenance, reservation change, complaint, cleaning). Auto-handle high-confidence ones and flag the rest for ops. Add a lead-qualification score on WhatsApp replies feeding Pipedrive stages.
- **Dev tooling** (hours): Use a decision model as a cheap gate in your agent loops, for example "is this tool result suspicious?" or "did the agent finish the task?", instead of a full LLM call.

### 4. Agent teams cost up to 5.1x more for little measurable quality gain
Vals AI found that agent teams cost 1.8x to 5.1x more than a single agent on Vibe Code Bench. Only one of four comparisons improved significantly: GPT-6 Sol at medium reasoning scored 7.3 points higher. In Anthropic's own data with Opus 5.5, quality plateaus past about ten agents (knowledge base: 0.53 with 1 agent, 0.70 with 10, 0.74 with 100). A separate study, covered by Ars Technica, found that coding agents generate more code but not more software, because human review becomes the bottleneck.

**Sources:** [The Decoder](https://the-decoder.com/ai-agent-teams-waste-massive-tokens-for-barely-measurable-quality-gains-research-finds/) · [Ars Technica](https://arstechnica.com/ai/2026/10/ai-coding-agents-generate-more-code-but-not-more-software/) · [HN: Why are coding agents so dumb?](https://news.ycombinator.com/item?id=50020947)

**Why it matters:** Multi-agent setups look like "more compute equals better results", but coordination overhead eats most of the gain. Parallelism buys speed (Noam Brown reports about 2x faster at 2x cost with four agents) more than quality. It helps on parallelizable work like web research and math, and not on tightly coupled work like writing. Before adding subagents in Claude Code, measure against a single agent.

**Try it in 15 min:** Take one repeatable task, such as "write tests for module X". Run it once with a single `claude -p` call and once with your subagent setup. Compare tokens, wall-clock time and review effort.

### 5. Vercel Pro: deployment storage billing starts, with 30-day retention. Deadline Oct 23
Deployment and Functions Storage billing starts for all Pro teams at $0.10 per GB-month. The start date is in your email. The retention window changes to 30 days, and deployments older than 30 days will be deleted starting October 23 unless you opt out in retention settings before then. Deleted deployments can't be used for rollback. New Pro teams default to 30-day retention. Settings already at 30 days or shorter don't change.

**Sources:** [Vercel – billing](https://vercel.com/changelog/deployment-storage-pricing-expands-to-existing-teams) · [Vercel – new team default](https://vercel.com/changelog/new-pro-teams-now-default-to-30-day-deployment-retention)

**Why it matters:** Agents deploy often, so stored deployment history grows quickly. Vercel is passing that cost on. If you rely on old deployments for rollback or audit, you need to act before Oct 23.

**Try it in 15 min:** Open your team's Usage page and check storage per project. Then open the [Deployment Retention Policy](https://vercel.com/docs/deployment-retention) and decide whether to change retention. The [optimization guide](https://vercel.com/docs/deployment-storage/optimize) covers moving large assets to Vercel Blob and shrinking function bundles.

### 6. Postman's Agent Mode: patterns for tool sprawl, schema-based reads and context
AWS and Postman describe how Agent Mode runs on Bedrock for 40 million developers. Postman saw tool-selection errors rise once more than about 40 tools were visible. It now narrows 170+ tools to about 15 per task: a root agent looks tools up by embedding in a vector database and hands the subset to a context-isolated sub-agent. For reads, it replaced many narrow views with one query tool over ClickHouse tables, so the agent writes joins and aggregations against a visible schema. Postman found that missing or wrong context caused more failures than missing capabilities. It built per-entity context handlers and treats the context window as a scarce budget.

**Sources:** [AWS ML Blog](https://aws.amazon.com/blogs/machine-learning/how-postman-runs-agent-mode-for-40-million-developers-on-amazon-bedrock/)

**Why it matters:** These are practical MCP-server design rules. Keep the number of exposed tools small, expose a schema plus a query tool instead of one tool per question, and distill context rather than dumping raw objects. They apply directly to MCP servers you build over your work data.

**Try it in 15 min:** Count the tools your busiest agent or MCP server exposes. If there are more than about 30, try a "search tools, then load" pattern, or collapse several read tools into one SQL-over-schema tool against a read-only Supabase role.

**Product ideas:**
- **Work** (days): A read-only MCP server over your data lake or Supabase. It exposes schemas plus one query tool so ops and sales staff can ask about occupancy, revenue per property or funnel conversion, without building a tool per report.

### 7. EmbeddingGemma 2: open multimodal embeddings, Apache 2.0
Google's `embeddinggemma-2` is a 740M-parameter embedding model. It has a 270M text backbone plus optional vision and audio encoders. It supports text, image, video and audio in one shared space, 100+ languages plus code, and an 8,192-token context. Output is 768 dimensions, with Matryoshka truncation to 512, 256 or 128. Use bf16 or fp32, not fp16. A GGUF build from Unsloth is also trending.

**Sources:** [Hugging Face](https://huggingface.co/google/embeddinggemma-2) · [Unsloth GGUF](https://huggingface.co/unsloth/embeddinggemma-2-GGUF)

**Why it matters:** Embeddings turn content into vectors so you can search by meaning. Matryoshka means you can cut the vector to 256 dimensions and keep most of the quality, which saves storage and speeds up pgvector. A shared multimodal space lets text queries find images, for example "balcony with sea view" against listing photos. The model supports Portuguese and is cheap to run.

**Try it in 15 min:** Run the `sentence-transformers` snippet from the model card with `truncate_dim=256` and `prompt_name="SearchQuery"` / `"Document"`. Embed 50 listing descriptions and test a few Portuguese queries.

**Product ideas:**
- **Work** (days): Embed property photos and descriptions into pgvector, then let sales search units by natural-language preferences ("quiet, near the beach, 2 bedrooms") and send matches to leads.

### 8. Talorys: a self-hosted personal agent on Cloudflare's free tier
Talorys is an open-source single-user assistant that deploys into your own Cloudflare account. It has chat, memory you can edit, tasks, notes, reminders and optional AI routines, with no telemetry. Setup is `npx create-talorys@latest` (Node 22+). It falls back to working without AI when the Workers AI quota runs out.

**Sources:** [GitHub](https://github.com/rociiu/talorys) · [HN discussion](https://news.ycombinator.com/item?id=50031614)

**Why it matters:** It's a working reference for a small agent on edge infrastructure, covering memory, scheduling and a degrade-gracefully path. It's useful to read before building your own. One caution: a related HN story covers a personal agent that posted bank details to a company Slack, so check what any agent can see and post.

**Try it in 15 min:** Run `npx create-talorys@latest` in an empty directory with a free Cloudflare account. Read how it stores memory and schedules reminders, and run `npx create-talorys@latest doctor` afterwards.
